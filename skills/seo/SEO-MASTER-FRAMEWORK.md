# SEO Master Framework

## 1. System Architecture
This repository contains a modular, interconnected SEO Knowledge Base designed for AI Agents and Senior SEO Architects. 

The framework is divided into:
- **Foundational SEO**: Core concepts, keyword logic, intent, topical mapping.
- **Technical SEO**: Crawling, indexing, rendering, speed, and architecture.
- **Content & Semantic SEO**: Topic clusters, E-E-A-T, NLP, Entity optimization.
- **Off-Page & Authority**: Backlinks, PR, Entity associations.
- **AI Search & Emerging**: AEO, GEO, LLM optimization, Retrieval-Augmented Generation (RAG) visibility.
- **Specialized SEO**: Local, Ecommerce, App, Video, News, Enterprise.
- **Operations & Automation**: Python, n8n, GSC/GA4 integrations, auditing.

## 2. Core Operational Philosophy
Every SEO action evaluated by this framework must pass the following multi-dimensional analysis:

1. **User Intent Matching**: Does this change satisfy the underlying user intent more effectively than competitors?
2. **Technical Feasibility**: Can search engines effortlessly crawl, render, parse, and index this information?
3. **Semantic Relevance**: Are the right entities, relationships, and attributes explicitly defined and mapped?
4. **Authority & E-E-A-T**: Does this change strengthen the perceived authority and trust of the domain/author?
5. **Risk vs. Reward**: Is this a sustainable white-hat technique, a calculated gray-hat experiment, or a high-risk black-hat tactic?

## 3. The Continuous SEO Lifecycle
1. **Discovery & Auditing**: Run `SEO-AUDIT-FRAMEWORK.md`.
2. **Prioritization**: Use the Prioritization Engine to score tasks (Impact × Confidence × Search Opportunity ÷ Effort).
3. **Execution**: Invoke the specific domain skills (e.g., `technical-seo`, `content-strategy`).
4. **Validation**: Validate using testing protocols and schema validators.
5. **Monitoring**: Track indexing, GSC anomalies, and SERP shifts.
6. **Recovery/Adjustment**: Revert or pivot based on algo updates or negative velocity.

## 4. Agentic Interaction Model
When an AI agent interacts with this framework, it should:
- Read `SKILLS-INDEX.md` to identify the required skill.
- Read the corresponding `SKILL.md` file for deep domain logic.
- Follow the `Decision Logic` and `Step-by-Step Workflow` documented in the skill.
- Avoid assumptions outside of the documented taxonomy.
