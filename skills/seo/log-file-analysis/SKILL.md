# Log File Analysis

## Purpose
To extract and analyze the raw server logs to see exactly how, when, and where search engine bots (like Googlebot) are crawling a website.

## What This Skill Does
Removes the guesswork from Technical SEO. While tools like Screaming Frog simulate how a bot *might* crawl your site, Log File Analysis shows exactly what the bot *actually did*.

## Core Concepts
- **Server Log**: A text file generated by the web server (Apache, Nginx, IIS) that records every single request made to the server.
- **User-Agent**: The identifier of the bot making the request (e.g., `Googlebot/2.1`).
- **Hit**: A single request for a file (HTML, CSS, image) recorded in the log.
- **Crawl Budget Waste**: When log files reveal Googlebot spending thousands of hits on useless parameter URLs instead of your money pages.

## Step-by-Step Workflow
1. **Log Extraction**: Export access logs from the server (usually requires DevOps/IT assistance).
2. **Filtering**: Use a tool (Screaming Frog Log File Analyser, Splunk, or a Python script) to filter the logs to only show requests from verified search engine user-agents (to exclude spoofers and spam bots).
3. **Analyze Crawl Frequency**: Identify which URLs Googlebot crawls daily vs which URLs it hasn't crawled in months.
4. **Identify Errors**: Find URLs returning 404, 500, or 302 status codes specifically to Googlebot.
5. **Action**: If Googlebot is stuck in a spider trap (crawling infinite filter combinations), update `robots.txt` to block that path.

## AI Agent Instructions
IF performing Log File Analysis:
1. INGEST raw server log lines.
2. FILTER by User-Agent matching `Googlebot`.
3. AGGREGATE hits by URL path.
4. IDENTIFY patterns of high-frequency crawling on non-indexable or low-value URLs.
5. RECOMMEND `robots.txt` disallows for those paths.
